# Binary and document provenance

Every non-source file this repository ships has an origin, a license, and an
analysis note. This exists so a license or supply-chain audit has a written
answer for each binary instead of an unexplained blob.

Scope: files that are not plain source text. All project-owned source carries
a `Copyright (c) 2026 EdgeImpulse Inc.` line and the SPDX identifier
`BSD-3-Clause-Clear` in its header; it is not repeated here.

The authoritative statement of what is shipped versus what is fetched at
install time is [NOTICE](../NOTICE).

## Model artifacts — not shipped

No trained model is distributed here. Both `model.pte` and the NPU-lowered
`model_qnn.pte` come from your own run of the learning block in the
**example-executorch-qnn** repository, and `models/` holds only `labels.txt`
until you put a model there.

**Analysis:** a trained model is a derivative of its training data, so the
provenance and consent position recorded in [dataset.md](dataset.md) would
govern a `.pte` as well as the images. Keeping models out of the repository
means nothing derived from the training images is published at all, which is
the simplest position to hold and the reason `models/*.pte` is in
`.gitignore`.

For whoever does train one: the classifier is fine-tuned from torchvision's
ImageNet pre-trained MobileNetV2 weights, which torchvision distributes under
BSD-3-Clause. A `model.pte` from that block is an XNNPACK-delegated CPU program
and carries no compiled Hexagon binary or Qualcomm runtime component;
`model_qnn.pte` is compiled for Hexagon v73 and does not run elsewhere.

## Android preprocessing test fixtures

| Path | Count | Bytes |
|---|---|---|
| `rps-android/core/src/test/resources/golden/*.rgba` | 6 | 2,764,800 |
| `rps-android/core/src/test/resources/golden/*.nchw` | 6 | 1,056,768 |

**Category:** raw test fixtures — uncompressed image buffers and the tensors
derived from them.

**Origin:** generated by
[`rps-android/tools/make_golden.py`](../rps-android/tools/make_golden.py) in
this repository. The `.rgba` files are synthetic input images; the `.nchw`
files are the expected preprocessing output for each, used by
`PreprocessGoldenTest` to prove the Kotlin and Python preprocessing agree.

**License:** `BSD-3-Clause-Clear`, as works of this project.

**Analysis:** these are the only raw image buffers in the repository, so they
warrant an explicit statement. The images are **synthetic**: a procedurally
generated color gradient with a solid circle. They contain no photographic
content, no people, and no camera capture. They are reproducible by re-running
the generator. The file names encode the orientation, ROI, and input size each
case covers.
